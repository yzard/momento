# Places / Faces overlay 与误检排除实施计划

日期：2026-09-10。状态：已实施，验证结果见文末。
适用：WebGUI、Android、Momento 后端。

## 1. 目标与现状

- Places、Faces 详情覆盖在原列表上，关闭后保留原列表的滚动锚点、分页数据和选择状态。
- Faces 选择栏展示已选人脸缩略图。
- Face group 详情标题显示该组 ID。建议统一为 `Face Group #123`；这里使用 faceGroupId，不使用代表照片 ID 或某一条检测 face_id。
- 支持将选中组、或某组内选中媒体对应的人脸标记为“不是人脸”。只排除检测区域，不删除原媒体，也不禁用整张媒体的人脸检测。
- 排除记录在重新检测、重新分组、重启后仍有效；管理员 Clean AI Face Data 明确清除这些记录。

实施前：Web 的 Faces/Places 根据路由参数直接替换列表组件；Android 的详情分支同样替换集合内容。Face group 详情暂未接入媒体多选。Merge 是管理员操作；普通用户目前不能通过现有选择栏完成误检反馈。

## 2. 已确定的产品规则

- 只有管理员可以标记“不是人脸”，与 Merge 的权限一致；两端隐藏普通用户的操作入口，后端也强制校验管理员身份。
- 排除对所有能访问对应媒体的用户生效。共享的有效人脸集合排除匹配区域，并更新受影响的分组、代表图及手动锚点。
- 操作者仍只能处理自己有 media_access 的具体检测，不能借 group ID 修改不可见媒体。
- 普通用户继续浏览人脸列表与详情，不能调用 Merge 或误检排除接口。

这不是修改模型参数或训练模型。“不再检测出来”的可验证承诺是：再次运行检测后，已否定的同一媒体区域不会重新进入任何用户的有效人脸列表；底层模型仍可能产生候选框。

## 3. 两端详情改为 overlay

### WebGUI

- 保持 Places/Faces 列表组件挂载，在其上渲染独立滚动的详情 overlay，复用现有详情数据读取和媒体查看器。
- 列表到详情使用 history 状态记录背景页面，保留可复制的详情 URL；直接访问详情 URL 时建立正常的列表背景及关闭回退路径。
- 详情关闭、浏览器后退、非输入控件中的 Backspace 只关闭最上层。Escape 同样关闭最上层；输入框、可编辑区域中的 Backspace 仍用于删除文字。
- 媒体查看器位于详情之上：第一次返回关闭查看器，第二次关闭详情，随后回到原列表位置。
- overlay 打开时锁住背景滚动和交互，限制焦点范围；关闭时恢复原入口焦点。避免背景分页观察器在遮挡期间继续自动拉取。

### Android

- 调整 MainShellState 与主界面组合方式：Places/Faces 列表留在背景，详情独立叠加，而非只渲染当前详情分支。
- 保存并复用 LazyGridState、已加载页与选择集；系统返回、返回手势及详情返回按钮按查看器 → 详情 → 列表逐层处理。
- 阻止背景触摸和重复分页；必要状态使用现有保存机制覆盖旋转与页面恢复。

### 数据修改后的返回位置

- 单纯浏览返回时不清空列表、不重新跳到顶部。
- Merge 或排除导致列表排序变化时，以原可见 group/place ID 和像素偏移为滚动锚点；锚点消失则使用最近仍存在的邻居，避免错误地坚持原索引。
- 通过局部数据更新与分页协调避免移除项目后出现跳项、重复项。后台失效刷新不应重建整个列表组件。

## 4. Faces 选择栏与详情标题

- 两端选择栏加入横向可滚动的小人脸缩略图，按选择顺序展示，带 ID 辅助标识与可访问性说明；点击可取消对应选择。
- 图片使用正常 thumbnails，复用现有认证与缓存；加载失败仍保留该组可识别的占位项。
- 选择栏保留 Clear；Merge 仍需至少两组且具备管理员权限；新增管理员专用 `Not a face`，至少选中一组时可用。
- 普通用户不显示误检操作入口；管理员的选择模式同时支持 Merge 与误检排除。
- 详情标题统一为 `Face Group #{faceGroupId}`，媒体数量仍独立显示。列表 tile 继续保持图片加 media 数量，不重新加入 ID 文本。

## 5. 精确的误检排除语义

### 从 Faces 列表操作

- 后端把选中组解析为操作者当前可见的具体 face 检测集合，以提交时有效的成员快照为准。
- 操作对象是这个快照，不永久拉黑 group ID，也不自动否定将来加入该组的其他媒体。
- 提交前展示作用域、涉及的人脸与媒体数量，并明确“不会删除照片或视频”。处理中阻止重复操作；失败保留选择并显示可重试错误。

### 从 Face group 详情操作

- 仅管理员接入用于误检排除的媒体多选与底部操作栏。选择媒体仅限定候选范围，后端再按当前 group 成员精确解析 face 检测。
- 一张媒体中其他组的人脸不受影响。若同一媒体在当前组里有多个人脸检测，展示对应裁剪图/框供逐个确认，避免把混入同组的真人脸一并清除。
- 成功后移除已排除成员并更新计数与代表图；组不再有可见成员时关闭详情，返回保留位置的列表。

## 6. 后端持久化与再次检测

- 增加独立的误检排除记录，与可重建的 media_faces 行及 face group ID 解耦。
- 记录全局排除对象与管理员操作者、稳定媒体内容或输入身份、帧身份（适用时）、规范化方向下的检测框与必要匹配特征，以及创建时间。
- 再检测匹配限定在同一媒体内容和帧内，使用检测框重叠、中心距离和尺寸约束容忍框的小幅变化；不按整张图片、group ID 或全局 embedding 拉黑。
- 用临近真人脸、重叠框、框偏移、输入方向变化的固定样本确定匹配阈值；先写回归契约，再定数值，不能仅凭经验写一个宽泛阈值。
- 排除记录不随普通重检测、自动分组、手动 Merge 或派生缓存清理删除。管理员完整 Clean AI Face Data 清除它；普通 face grouping 清理不能意外解除排除。
- 排除写入与有效成员/代表图更新使用事务，并遵循现有有界 SQLite writer 调度；读取继续使用受保护 reader lane。
- 与正在运行的检测及分组发布协调：最终持久化/发布必须检查当前排除状态或版本，使排除前启动的任务不能重新发布被否定的人脸。请求重试幂等；重启后恢复保持一致。
- 在结果持久化前筛除被排除区域，修复被排除的手动锚点与空组；读取路径也不能暴露等待清理的已排除检测。文件清理由现有独立调度阶段处理，不在 API 网络线程内执行。
- 新增当前 SQLite schema 与测试夹具，按仓库政策不引入自动 migration，不删除既有用户数据库。交付时明确现有数据目录与新 schema 的部署限制。

## 7. API 与缓存

拟新增统一的 `POST /api/v1/faces/reject`：使用互斥的明确选择类型，例如 groups（groupIds）或 faces（groupId、faceIds）。详情多选先取得当前媒体内的检测 ID/裁剪信息，再提交具体 faceIds；不得仅用 mediaIds 删除该媒体全部人脸。

- 强制 RequireAdmin 管理员认证，逐项校验可见性、当前组归属和批量上限；过期选择返回明确冲突，不能静默扩展到新成员。
- 返回实际排除数、受影响组及其最新状态，供两端更新列表、详情和选择栏。
- 所有普通响应使用 typed JSON/camelCase，错误使用现有 AppError/detail；两端更新共享 API 调用和模型。
- 排除后失效 Faces 列表、详情、代表图，以及依赖人脸结果的查询；Android 的离线 Faces 快照也必须失效，避免离线重新显示已否定的结果。
- 代表图改变时更新缓存身份或验证信息，防止沿用旧缩略图；通过统一的数据变更通知或现有验证机制让其他用户刷新相关 Faces 缓存；无关功能缓存保持不变。

## 8. 实施顺序与验证

1. 按“仅管理员操作、全局生效”确定 API/schema 契约；overlay、选择栏和标题工作可以独立进行。
2. 完成两端 overlay 导航与状态保留，覆盖浏览器 history、Backspace 输入保护、Android 返回、详情内查看器的逐层关闭。
3. 完成持久排除记录、匹配策略、事务与并发发布屏障、管理员 clean；补后端测试。
4. 接入两端组选择、详情 face 选择、提交反馈与缓存失效。
5. 验证同图“真人脸 + 误检”、同组多框、不可见成员、重复提交、权限变更、重检测框偏移、重启、Merge/检测并发以及 Clean 后允许重新出现。
6. 验证长列表多页滚动 → 详情 → 查看器 → 返回；以及删除当前滚动锚点、组清空和代表图更新。
7. 运行相关 Rust release 测试、Web 类型/样式/交互测试，以及 Docker Android verify 和必要的 instrumented-test。Android 全部构建和测试只通过 build_android_client.sh。
8. 同步 faces 架构说明和使用说明；按仓库布局要求把实际触及的不规范 Faces 路由/处理模块迁入对应资源目录，并同步镜像测试，不做无关目录迁移。

验收：两端返回原列表位置；选择栏能看见选中人脸；详情显示组 ID；排除仅作用于明确选中的检测；同图其他真人脸保留；再次检测与重启不会恢复被排除区域；管理员完整清理可重置排除。

## 9. 实施结果

已完成两端 overlay、选择栏缩略图、组 ID 标题、管理员全局排除、逐检测裁剪选择、
持久匹配、并发分组 revision 屏障及缓存失效。实际接口返回 rejectedCount，客户端重新
加载组状态；每次最多 200 组、4096 个检测。视频匹配使用原始帧时间戳，允许检测框小幅偏移。
排除事务同时登记孤立裁剪的持久清理任务。

部署需要新的数据库/数据目录；未修改或删除现有用户数据库。完整契约见
[Faces 架构说明](../architecture/faces.md)。

验证记录：后端全套 62 个单元测试和 573 个集成测试通过；最后的批量清理与
代表图分页调整后，Faces 相关 29 个测试通过。Web 全套 231 项通过，新增精确
多框选择后 Faces 专项 7 项通过，类型检查和相关 lint 通过。Android Docker
verify（编译、JVM 测试、lint）通过；模拟器 33 项中 32 项通过，两次运行均有
PasswordChangeInstrumentedTest 的组件显示断言失败。该独立密码表单测试与本次
Faces/Places 修改无直接关联，尚未修复；不宣称模拟器全套通过。
